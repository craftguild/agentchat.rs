# Native acceptance

Actual Codex/Claude behavior is separate from offline API/type or synthetic workload coverage. Use the maintained preparation tooling with an explicitly owned disposable project and read the selected tool's `--help` before execution. No command in a documentation check authorizes a real host campaign.

## Boundaries

Record the exact AgentChat and native images, live API/version observations, original boot/PID/kernel-start/user, project/root/generation and controller inputs. Complete normal host authentication and trust prompts. Do not substitute HOME or CODEX_HOME, copy credentials, weaken approval controls or signal a shared server.

Use private `AGENTCHAT_HOME` and `AGENTCHAT_USER_CONFIG_ROOT` fixtures. Fresh setup, preserving installation and actual native launch have distinct side effects and must be intentional. Known synthetic fixtures do not certify ordinary global configured discovery or a naturally absent daemon's first-start path.

## Required observations

- Complete maximum-size original bodies and mixed Message/Notice FIFO, without truncation or unintended explicit reads.
- Current exact-root participation, explicit Leave/rejoin, supported switches and original-owner loss without borrowed authority.
- Complete original acceptance and independent automatic/explicit reads under the ACK-free lifecycle.
- Original-result-loss cuts retaining Unknown/head/token/attempt and refusing blind resend or uncertain successors.
- Original receipt recovery only through the supported native mechanism.
- Bounded resources, original errors, stopped/gone owner facts and normal cleanup of owned helpers, without affecting user sessions or shared daemons.

Historical fixture packages may encode superseded wire formats. Their offline tests preserve the corresponding historical contracts; do not run an old native matrix as current acceptance. Current [delivery](../design/delivery.md), [compatibility](compatibility.md) and [verification](verification.md) govern claims.
