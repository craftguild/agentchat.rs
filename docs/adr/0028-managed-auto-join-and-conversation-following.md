# ADR 0028: Managed auto-join and conversation following

## Status

Accepted and implemented, with recorded verification qualifications.

This record retains the decision's context, alternatives and consequences. Read it with the [current contracts](../README.md) and [verification scope](../guides/verification.md). Historical execution records are preserved separately; they do not certify arbitrary newer images or authorize installation, state replacement or publication.

## Context

A fixed-root wrapper can prove the original CLI's lifetime but cannot tell that the user moved its display to another conversation. Continuing addressed input to the hidden old root can start unwanted work and consume tokens. The user prefers managed launch to mean participation in the conversation currently used in that terminal, including supported `/new` and `/resume` transitions.

The inspected Codex hooks provide a session ID, but the tested callbacks run under the shared server. Two CLI-specific environment markers did not reach them, and SessionStart arrived with first input rather than the observed switch. This route alone could not associate a new root with the departing managed CLI. That scoped result is not a claim that every possible future hook is inadequate.

A disposable dedicated WebSocket proxy observed each CLI's control requests and responses without changing message payloads. Native `/status` matched the new IDs for `/resume`, return to a previously used root and `/new`; another CLI retained its root. Cancellation, an invalid selector and an owned transport disconnect were also observed. Some successful transitions had no old-root `thread/unsubscribe`, so that notification cannot be the sole switch boundary.

## Decision

The accepted 2026-10-30 [ADR 0027 startup correction](0027-process-continuity-across-executable-updates.md#boundaries-and-migration) removes filesystem device-number equality from native routing, initial image and durable Claude signal validation on both operating systems. Retained valid records remain readable after device renumbering; a fresh owner still requires positive prior-owner loss and exact native readiness. This does not resume an old participation generation or resolve an unknown delivery result.

### Managed launch is consent to participate

Keep `agentchat launch codex|claude [--resume EXACT_ID] [--name NAME]`. After normal trust/authentication and actual exact-scope integration readiness, the verified managed launch invokes the shared application activation/Join operation automatically. Successful participation requires its committed result; spawning a process or seeing a thread ID is not enough. Establish initial participation before admitting the first input that requires AgentChat.

Retain explicit Join. Already-active Join returns current participation without another generation. After Leave, explicit Join may activate a fresh generation while the original managed owner remains current. A supplied name retains the existing immutable-handle validation; switching does not rename an old agent.

An unmanaged fresh conversation cannot create launch authority through Join. Return the existing `session_required` envelope with actionable managed-launch or exact-ID managed-resume guidance. Retain the accepted same-UUID Codex frontend limitation: another frontend can share the originally authorized conversation, but cannot become its owner or extend its lifetime. Do not revive caller-terminal attribution as a prerequisite for that accepted case.

That sharing applies only while the original managed observation authorizes the root as current. After its observed departure, a surviving same-UUID frontend cannot revive the old binding merely because the original owner PID is alive. Only a verified managed return or new managed launch can authorize it again.

### Follow distinct conversations inside the launch project

Track the exact host-issued root, original native CLI/supervisor identities, connection observation and transition order. A host adapter supplies typed lifecycle facts; shared application policy owns activation, project restrictions, membership, generations, recipient queues and naming under ADR 0022. CLI/MCP transports do not acquire separate business rules.

| Observed managed event | Required application behavior |
| --- | --- |
| Initial verified ready root | Automatically Join at its committed boundary |
| Successful distinct-root `/new` | Retire old recipient work and automatically Join the verified new root |
| Successful distinct-root `/resume` | Retire old recipient work and automatically Join the verified selected root |
| Picker cancellation without an activation request | Preserve the existing binding and participation |
| Failed or unresolved switch | Do not join the candidate; preserve the old mapping, but resume its delivery only with sufficient current evidence |
| Same-root reconnect or repeated activation observation | Restore only an already-active generation; never undo Leave or duplicate Join |
| Switch to another project or unresolved project scope | Stop old-root delivery; do not join the target; provide managed-relaunch guidance |
| Positive original-owner loss | Stop delivery and retire recipient work independently of shared-server survival |

At an observed activation attempt, serialize a delivery fence with native submission authorization before forwarding that activation request. No further old-generation write may be authorized after the fence. Correlate the originating managed connection, request and successful response before accepting the target; validate the requested/resolved ID and project. Do not select a target from history reads, global notifications, a directory, display name or PID alone. The application must also recheck the exact predecessor's durable root-change fact, host, distinct root identity and original owner inside the activation transaction. An internal `DistinctRoot` cause is correlation data, not authority and cannot manufacture departure evidence by itself. A provisional transition fence may suspend target authorization and delivery, but it is not a positive departure and cannot authorize predecessor retirement, replacement or activation.

Activation authority and delivery authority are deliberately distinct. Shared Join and managed activation continue to use the verified launch identity. Native dispatch, receipt polling and final-current checks use a provider-independent delivery identity, which the admitted host withholds until its exact committed start marker exists. Before a recognized Codex transition can enter the server, the original supervisor durably fences the tracked binding. A byte-stream hook holds only the final transit chunk until that fence exists; it never buffers the complete native request. The correlated native reply is forwarded before asynchronous same-project activation or cross-project retirement. Target delivery remains disabled until that exact activation and response-write evidence commit. Ordinary native input and responses do not wait for AgentChat readiness. A lost write, ambiguous observation or application acknowledgement keeps delivery fenced; it never grants a target or authorizes terminating a running native frontend. Cross-project retirement creates no target participation or target start marker.

Before the first physical readiness, an unloaded conversation still needs its native resume request to reach the server. The supervisor may acknowledge one initial candidate only while its original child is current and no binding has ever been tracked. Retain that exact event ahead of subsequent proxy events and replay it into Control before managed activation; early native progress grants no participation or delivery authority. Serialize this exception with first binding tracking. Once tracked, the ordinary durable pre-entry fence applies. Do not cancel a pending readiness/context preparation to service the initial candidate, and do not extend the startup deadline to mask this circular wait.

The same ordering applies when the native CLI's initial resume overlaps its first managed Join. After physical readiness, the supervisor retains an explicit initial activation intent and its original request UUID, context, name and cause. It processes exact Candidate/RolledBack outcomes before retrying that intent, including a fence created during Core verification or attachment. Unknown or an unsettled distinct-root success cannot release the old initial context. A lost application reply or observation acknowledgement suspends AgentChat while the physical-ready native child and transparent forwarding continue. A historical successful receipt after Leave never restores attachment or writes a new start marker. Owner, publication and readiness mismatches still grant no authority.

A known initial activation receipt ends mutation replay. Losing its first MCP connection can disconnect that incarnation before the supervisor attaches; Core must continue refusing a stale incarnation. Recover only the same retained agent, launch generation and join boundary through a newly verified descriptor. Keep one pending descriptor across ambiguous publication or attachment. Replace that pending descriptor only after exact current publication/physical proof and fence checks plus a typed Core read positively identify that same incarnation as disconnected while its original participation remains joined. Unknown, foreign or mismatched evidence grants nothing; a later Leave remains inactive.

After descriptor recovery, recheck current participation before completing a previously known initial result, including a retry after a failed start-marker write. An already proved startup marker is historical for its immutable owner, generation, endpoint and native scope; preserve its original bytes rather than rewriting it for a replacement incarnation. Neither that marker nor an old successful receipt substitutes for current Core authority.

Treat `thread/unsubscribe` as additional departure evidence, not a mandatory completion signal. Reject stale responses and lifecycle callbacks from older connection/transition epochs. Unknown transport or switch state suspends delivery; it cannot authorize either root. A definite failed switch may release the old fence only when the retained ownership and native client behavior establish a safe rollback. Otherwise report the suspended state and relaunch guidance.

The supported target must resolve to the launch's authorized project UUID and canonical project reference. A worktree/directory may differ while remaining in that project. Do not install another project, move membership between projects or infer a conversation from its directory. For another project's conversation, instruct the user to exit and run `agentchat launch HOST --resume EXACT_ID` from the appropriate installed project. Returning to a verified root in the original project is a new supported transition and may automatically participate again.

A confirmed departure retires old recipient work even when the target is outside the project and therefore cannot join. Do not keep accumulating old-root delivery while the CLI remains open elsewhere. Unresolved transitions remain suspended under the existing bounded-queue and uncertainty rules rather than guessed dead.

This decision covers ordinary root `/new` and `/resume`. A fork, subagent or arbitrary server-loaded thread does not acquire managed authority merely by appearing in an event stream. Other native switching routes need their own verified activation semantics before being claimed as supported.

### Conversation identity, Leave and backlog boundaries

Keep the existing project-scoped `(host, host_session_id)` participant model. For `/resume`, reuse that conversation's retained agent ID and handle if present; otherwise allocate a new participant and generated handle. `/new` receives a new participant and generated handle. Do not transfer a departing agent's identity, reservations, read receipts or task acceptance to an unrelated conversation.

Leave suppresses participation for the current root, not the rest of the managed CLI lifetime. Switching to a distinct supported root automatically joins it, including a later return to a previously left root. Repeating the same root or recovering its connection alone does not undo Leave; explicit Join remains available. Duplicate observations must not create repeated generations.

Each distinct-root activation uses a fresh participation boundary. Discard the old generation's undelivered recipient work; do not transfer it, replay inactive intervals or drain an offline backlog on resume. Shared channel history remains available to explicit reads and the context-free viewer.

A same-root runtime/transport recovery is not a distinct-root switch. It retains the original active generation and unresolved-head rules, without automatically joining an explicitly left root. Ambiguous native submission remains blocked: neither reconnect nor a repeated same-root observation permits resubmission or successor input. A genuine root change retires old recipient work without rewriting its historical acceptance or uncertainty.

The fence cannot recall bytes already submitted or input accepted by the host. Do not interrupt an existing turn to erase that work or claim zero hidden work after an earlier submission. The promise is no continued new delivery to the departed root after the observed fence. Preserve complete-body FIFO, automatic host-owned ACK, explicit read/task separation, native approvals and interruption behavior. Codex Esc remains independent of Leave.

### Codex transport and Claude hooks

For Codex, route the managed native CLI through a private dedicated transparent connection to its existing shared server. Forward ordinary messages unchanged; observe only the control metadata needed to associate that CLI and its supported root transitions. Do not rewrite, save or log conversation bodies, transcripts, credentials or arbitrary RPC parameters. Store only bounded allowlisted lifecycle metadata. Preserve native wire bytes without reframing WebSocket transport.

All native CLI/server traffic traverses this proxy, so it is technically able to access bodies. Not logging them does not remove that supply-chain trust boundary. The user accepts this tradeoff; there is no user-facing full-proxy mode flag. Limit implementation responsibility to lifecycle observation and transport forwarding, not prompt editing, model scheduling or extra Esc policy.

The 2026-10-28 user clarification supersedes the former four-method auxiliary allowlist: sensitive content must be excluded from observation and retention, not from forwarding. Every socket from the exact original native owner uses the same relay. Arrival order grants no RPC permission or foreground role, and there is no proxy connection-count or frame/message-size limit. Closing one socket cannot close its siblings. A failed new backend connection, including temporary socket-path absence, cannot revoke established streams. Kernel user, original PID/birth and supervisor checks remain mandatory; a same-user helper is not an authorized native owner.

Relay Unix bytes unchanged in independent directions, including the HTTP upgrade, URI, repeated and negotiated headers, native errors, fragmentation, masking, binary/control frames and half-close. Do not terminate WebSocket or synthesize native RPC errors, Pongs, retries, timeouts or replacement responses. Bounded transit queues apply backpressure without rejecting a large native message. Native endpoints retain their own protocol and resource limits. The existing five-second upstream connection setup deadline remains; it does not bound a native message or response. AgentChat acknowledgement waits remain bounded to 35 seconds independently of forwarding after exact ready tracking. Initial startup and authorization/filesystem-integrity failures retain their existing fail-closed cleanup policy.

The passive observer reads text-frame JSON incrementally through a bounded transit channel. A streaming serde visitor skips unknown values with `IgnoredAny`; it never constructs prompt/history/tool trees or assembles a native message. Decode only bounded keys, method, scalar ID, ephemeral and root metadata. Encoded method/ID/root bounds remain 128/8192/6146 bytes with a validated 1024-byte root. Observation keys and JSON structural depth are bounded to 128 bytes/levels; these are parser-state bounds, never native message limits. The observer owns only selected tokens and fixed-size transit chunks, and never logs or persists bodies, credentials or arbitrary parameters. Ordinary backend messages without a matching connection-scoped pending request need no JSON inspection. Raw native bytes are never reconstructed from parsed JSON.

Correlate responses by both socket identity and canonical request ID. Only a supported non-ephemeral `thread/start` or `thread/resume` request and its exact successful response can supply a candidate root; reads, server-initiated requests and global notifications cannot. Preserve duplicate-key/null semantics and exact resume-root checks. An overlapping candidate, unsupported encoding, oversized or unusable metadata makes observation uncertain: retain the durable fence, forward the native traffic, and require managed relaunch for participation recovery. Metadata limits never become native payload limits. No unsupported message can silently authorize the previous or target root.

The supervisor must refresh the observer's tracked binding before enabling a new participation generation after explicit Leave/Join and before restoring a same-generation context/incarnation. Original physical readiness is immutable; it authorizes only the same original live owner, endpoint and exact native/project scope. The tracked binding must match both the published context and current native route, rather than equal the original readiness descriptor. A positively departed generation remains ineligible even while its old root locator is retained. Serialize retargeting with durable fence creation. While a same-root switch is unresolved, refuse a different descriptor instead of transferring its exact pending fence. Only a definite matching rollback or delivered activation releases that barrier; Unknown never does. The original transparent-proxy certificate predates this later rejoin finding and cannot substitute for its focused correction. The focused follow-up verification records the correction and explicitly omitted full-suite/native UI/Linux scope.

The prior method-use archive retains its historical scope, including the failed preview rendering and backend-only observer limitation. Its allowlist and two-reader behavior are superseded, not retroactively validated. The current correction and tests are recorded in the scoped local verification. It does not certify actual native rendering, Linux, full workloads or adoption.

Treat a retained native AgentChat MCP's explicit failed, cancelled, disabled or authentication-required status as a terminal configuration failure, not as ordinary startup progress. Report native MCP recovery guidance independently of native transport. After a switched root's reply has been delivered, this failure cancels only AgentChat activation and retains the predecessor/Unknown fences. Keep the native terminal and subsequent RPCs running, create no target participation and never reload another frontend's MCP connections. Missing/not-started/starting status remains pending.

Pass the selected canonical directory through the native `--cd` option as well as the spawned process cwd when using the dedicated `--remote` endpoint. The preflight's remote launch without `--cd` created `/new` in the shared server's different default directory; explicit `--cd` retained the selected directory. This does not claim to fix all `/resume` picker filtering or native versions.

Claude retains its existing authenticated file/hook/native lifecycle route; do not proxy it merely for symmetry. Its adapter must establish the same root departure, new-root readiness and application activation boundaries through hooks under normal host controls. Current behavior for this new contract still needs actual native validation. Do not infer success from documented APIs or strings.

A `/new` ID can exist before the first user message while paginated turn history is still unavailable. Neither that expected state nor a successful `thread/start` alone proves MCP readiness, materialized history or completed participation. Validate initial and switched-root readiness through actual supported APIs; do not start a model turn merely to discover the root or bypass native trust.

## Interfaces, verification and rollout

No new public CLI/MCP command or result-envelope version is required by this decision. Keep shared Join idempotency and diagnostics. Internal lifecycle and routing records may need new typed facts/versioning; old fixed-root records must not silently acquire switch authority or undo an explicit Leave. Define and verify their compatibility before adoption. Existing ADR 0025 input frames and database/migration history are not changed by documentation publication.

R33/T31 in [acceptance](../guides/verification.md) owns new implementation verification: initial readiness/auto-join, new/resumed-root identity, names, Join/Leave, cancellation/failure/uncertainty, delayed and duplicate callbacks, project restriction, same-root recovery, original-owner loss and simultaneous dispatch. Exercise maximum complete bodies, native ACK/read separation and unknown-head recovery with the supported host controls on macOS and Linux. Prove both the Codex proxy route and Claude hook route; do not reuse historical proxy or direct integration results as a current-image certificate.

Apply ADR 0012: macOS workload timing remains a gate, Linux timing is reported, and Linux functional/durability/resource/native gates remain. Use focused checks during development and one grouped affected final wave. Keep completed goals, concurrent ADR 0027 verification and operational adoption separate. Tests use temporary `AGENTCHAT_HOME` and `AGENTCHAT_USER_CONFIG_ROOT`, without `HOME` or `CODEX_HOME` substitution, real profile changes or shared-server termination.
