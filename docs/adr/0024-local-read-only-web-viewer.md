# ADR 0024: Serve a local read-only GraphQL chat viewer from the agentchat binary

## Status

Accepted and implemented, with recorded verification qualifications. Later scope is amended or superseded by [ADR 0032](0032-delivery-state-machine-and-ack-removal.md). The React/generated-SDK and explicit human-write amendments below are current; historical Lit/read-only-only descriptions retain their original scope.

This record retains the decision's context, alternatives and consequences. Read it with the [current contracts](../README.md) and [verification scope](../guides/verification.md). Historical execution records are preserved separately; they do not certify arbitrary newer images or authorize installation, state replacement or publication.

## Context

Human observation currently uses terminal watch/history. The user wants a Slack-like viewer with channels, a scrolling channel timeline and a separate thread pane. It must show retained history even when an offline agent did not receive a message. Cancelling recipient delivery under ADR 0018 does not delete the shared message, and browsing that history must not rejoin an agent or restore its cancelled backlog.

The user selected Chigiri.rs from the pinned Chigiri upstream, embedded frontend assets and a local-only, unauthenticated, read-only interface. The original polling decision reflected Chigiri's lack of subscriptions at that time. Chigiri now implements typed subscriptions and official streaming bridges, and the user requested verification and adoption.

## Decision

### Launch, HTTP and runtime ownership

`agentchat viewer` discovers the initialized project through the existing CLI routing rules. It serves exactly that project for its lifetime, binds `127.0.0.1:0` and prints the actual `http://127.0.0.1:PORT/` URL after the listener is ready. Run in the foreground until Ctrl-C; do not automatically open a browser, initialize a project, install host integrations or launch a native coding agent.

Serve embedded assets and `POST /graphql` from the same origin. Expose a read-only Query/Subscription schema: no mutations, message composer or runtime administration. Do not expose an arbitrary project/path selector or a nonlocal listen address. No login or access-token mechanism is required. Restrict accepted Host/Origin values to this listener and do not enable permissive cross-origin reads. Browser content must not execute message-supplied scripts or access local files through an asset or image proxy.

Use distinct-connection GraphQL-over-SSE for subscriptions: POST the GraphQL document/variables with `Accept: text/event-stream` to `/graphql`, and consume `next`/`complete` events. Use Fetch streaming with an abort signal; native `EventSource` does not supply this POST request. Finite Query requests keep their JSON response negotiation. Do not add WebSocket, multipart, a JS proxy or an automatic periodic-polling fallback to this initial viewer. Bound HTTP connection admission and the number of active streams; enforce Host/Origin/path restrictions on streaming requests before Chigiri setup as well as on finite requests.

CLI composition uses the existing project-runtime connection/start operation; `agentchat-web` consumes the shared typed read interface from ADR 0023. It opens no database connection of its own. A context-free observer attachment holds runtime activity while the viewer is open, without participant identity or host heartbeats. On runtime restart, re-establish observation of the same project and resume reads. On viewer exit, close its HTTP/observer resources and leave the shared runtime and native hosts under their normal lifecycle rules. A single distributed executable can run a separate existing project-runtime process.

### Crate and generated-source boundaries

Add `agentchat-web` for HTTP, GraphQL adaptation, rendering and embedded asset serving. Its internal dependencies are `agentchat-core`, `agentchat-protocol` and its generated GraphQL contract support crate. It must not depend on `agentchat-store`, `agentchat-hosts`, `agentchat-runtime` or `agentchat-cli`. `agentchat-cli` supplies the runtime-backed typed reader and shutdown lifecycle. Business query policy remains in the common application layer.

Use the pinned Chigiri facade and Axum integration. Keep its generator, runtime and generated ABI compatible. Generate a dedicated product contract. Bind the schema to typed shared DTOs or typed Web projections, without a JSON-reconstruction bridge or ORM entities in GraphQL resolvers.

Use Chigiri's official SDK-managed Axum service through ordinary `Router::route_service`. Chigiri owns its supervision, source demand and SDK cancellation; do not duplicate its supervisor or assemble a manual driver/guard. AgentChat owns the listener, concrete native connections, local HTTP admission, runtime lease and signal source. Use the public `shutdown_on` hook with explicit Immediate or bounded Graceful options. Its outcome describes eligible SDK work, not native physical cleanup; separately bound and drain viewer-owned connections before returning or dropping the runtime. No-hook service release alone is not proof of coordinated drain. Propagate disconnect/shutdown to source cancellation. Bound upstream observer buffers separately from Chigiri's encoded-event buffers.

This amends ADR 0006 narrowly: provenance-verified Chigiri-generated Rust is exempt from the 400-code-line limit. Check its ownership manifest, generator/ABI, schema/configuration inputs, file hashes and deterministic regeneration. Fail on manual edits, unknown files or hand-written code hidden in the generated area. Keep generated product inputs in dependency, query-boundary and workload-source checks. All other product sources retain the same applicable checks. Hand-written backend, frontend and build/support code retain the size rule.

The generated contract is support code with explicit allowed dependency edges, not a new policy-bearing crate. Crate/source enforcement now validates the viewer graph and its narrow generated-source exception, including ownership, source inputs, exact regeneration and the other existing checks.

### Shared history and GraphQL reads

Expose the current project, all channel pages, a channel's root timeline, a root with replies, and bounded incremental changes. Read all stored messages under the project regardless of their recipient delivery state. Do not use an agent inbox as the history source, and do not create ACKs, read receipts, participants, leases or native wake work as a consequence of viewing. The user's 2026-10-25 sidebar amendment also exposes paged project identities through the existing typed `Agents` operation. Project-wide participation uses explicit `joined`, independently of posts or current connectivity. Project only `id`, `handle` and `joined`; omit host/session details. Refresh this list initially and after committed Subscription progress, without timer polling or another feed. Display its count next to the main channel title, since every joined project agent belongs to every channel. An unavailable roster supplies no guessed count.

The channel timeline contains root posts in creation order with reply counts. Selecting a root opens a right-hand thread pane. The root remains independently fetched at the reply snapshot, but the user's later 2026-10-25 amendment displays it as the first ordinary row in the same virtualized scroller as the replies, with no fixed root area or separate root scrollbar. Highlight the selected root only in the main timeline; the thread's root card keeps its normal white background. Closing the thread removes that main-timeline highlight. When replies exist, a horizontal border separates the thread root and replies inside their shared scroller. A fixed footer below the sidebar agent list shows only the build version and seven-character source revision. Build/dev startup generates sealed static metadata from the product Cargo version and source HEAD; source archives use `unknown`, and installed execution requires no Git/source access. The hash identifies a base revision, without asserting a clean tree. Initially load the latest 50 roots or replies; scrolling up requests 50 older items. There is no new Thread persistence model. Reply counts cover all retained replies, not only the loaded page. A reply to an older root updates its count without moving that root in creation order.

Add latest/backward windows and incremental change operations to common typed reads. Validate channel/root consistency and obtain related rows/counts under one snapshot; use bounded batched aggregates rather than per-message queries. Keep existing ascending history/search behavior compatible. Existing page/frame limits still apply: the UI may need several bounded pages to reach its target of 50 complete records, without truncating bodies.

Use project sequence cursors encoded as decimal strings, not timestamps, UUID ordering or JavaScript floating-point numbers. Preserve a captured snapshot head across each paging cycle. Incremental reads include replies needed to update loaded root counts and an open thread, including replies to old roots. Advance only through safely consumed/scanned data; do not jump to the global head while matching records remain. Drain continuation pages after a burst and deduplicate by message identity without hiding new rows. Root-history and thread cursors are independent. GraphQL response and render expansion budgets are finite as well as the underlying RPC pages; shortening an adapter page cannot skip its remainder.

### Subscription, recovery and flow control

Keep initial/latest/backward snapshots as finite Query operations. Subscribe to one project-wide typed change feed per visible viewer document, from an explicit exclusive `after` cursor. It supplies complete relevant message projections, root/reply identities, coherent reply-count updates and channel additions, not only a wake hint requiring a Query round trip for every message. Ignore changes irrelevant to an unloaded pane while retaining correct scanned progress. This read-only stream is separate from agent inboxes and native recipient delivery.

A snapshot includes its project identity and sequence watermark. Register observation before catch-up, replay retained changes after that watermark and then wait on committed-head notifications. Drain bounded pages immediately after a burst, without waiting for another event to release a continuation. Reconnecting with a cursor must include changes committed before subscription setup, as well as changes racing it. Never advance past matching data omitted by item, byte or render-expansion budgets. Cursor progress may cover explicitly scanned irrelevant events; it must not be inferred from heartbeats or the current global head.

Each active view retains its own snapshot watermark. When adding/changing a pane, establish its snapshot/live boundary, deduplicate by identity/sequence and ignore changes already covered by that snapshot. Replay from the oldest needed watermark or use a bounded setup buffer; if the buffer cannot retain the overlap, restart the affected snapshot/feed rather than skip it. Channel/thread selection generations reject stale results. Root-history and thread pagination remain independent of the project change cursor.

Use the default lossless `Backpressure` policy, not `DropOldest`. Set finite source/batch, encoded-event, queued-byte, connection and rendering limits together. Chigiri's default 64-KiB encoded-event limit cannot carry every legal 64-KiB body plus JSON/HTML overhead: explicitly configure a sufficient bounded limit and shorten batch pages within it. A single oversized computed HTML field falls back to escaped source under the existing render policy; the original body remains complete. Verify the fully encoded result, including extensions. At the qualified Chigiri revision, injection is still constrained by a 1-MiB hard event ceiling and a 4-MiB per-subscription retained-byte ceiling. Fit complete product records within those bounds; a requirement exceeding them needs an explicit producer contract revision, not silent truncation.

Backpressure may pause or terminate a slow source; it is not durable replay. Only advance the browser cursor after a complete, valid batch has been applied. On disconnect, terminal source failure, reported drop or bounded-buffer overflow, retain visible data and resume from that applied cursor. Deduplicate a replayed batch; do not treat the server's last local write as client receipt. A GraphQL error, malformed/incomplete event or unexpected delivery-drop metadata cannot advance progress. Validate project identity and cursor range on reconnect; a cursor invalidated by restoration or incompatible history requires a visible snapshot reset, not silent reuse or a jump to latest. Replay is AgentChat policy: Chigiri does not provide implicit replay, `Last-Event-ID` recovery or consumption acknowledgements. No delivery ACK or explicit read is added for browser receipt.

### Browser behavior and assets

The user-approved 2026-10-30 React migration replaces all Lit Web Components and state classes with React/TypeScript, React Router, Apollo Client, React Hook Form and Zod. GraphQL Tools loads and validates the `.graphql` operation catalog; GraphQL Code Generator with `typescript-generic-sdk` emits named operation methods and `getSdk(requester)`. A shared Apollo requester binds this generated SDK to the existing bounded link; runtime validators and live ownership remain app-specific. Views/services call the generated methods through `useSdk`. Generated TypeScript remains within the ordinary 400-code-line limit. Components use typed props and direct Tailwind utility classes. Retain small base, generated Markdown and coordinated-motion CSS; no Shadow DOM styling layer remains.

Embed Vite's static HTML/JS/CSS and asset metadata in Rust. No SSR or runtime Node service is introduced. One bounded Apollo transport preserves validated POST/SSE, visibility cancellation, exact checkpoint replay and explicit mutation retries. Apollo owns bounded immutable content; new React projections own snapshot-specific counts, timelines, unread holes, navigation and drafts. This supersedes both the original Lit choice and its earlier `@apply`/shadow-style amendments. The [current viewer contract](../design/viewer-contract.md) defines architecture, maintenance and requirement-to-test coverage.

Use a visible sidebar divider, Tailwind `rounded` message cards, and a floating `rounded-full`/shadow older-message island without a reserved strip. The later same-day navigation amendment below supersedes that older-message island with automatic upward paging and no older badge. Omit the main header's `Timeline` subtitle; retain thread reply counts. The subsequent 2026-10-25 header amendment places AgentChat and Live in one full-width page header above both columns. Bundle IBM Plex Sans for proportional text and IBM Plex Mono for inline/block code as same-origin WOFF2 assets. Use `text-sm` (14px) throughout, with `text-lg` (18px) for AgentChat and matching `text-sm` (14px) channel/thread titles, as amended on 2026-10-30. Message cards retain their `rounded-md` shape and shadow, with no card border. The later same-day spacing refinement uses `space-x-3` for status indicator/label separation and `rounded-md` for the active channel background as well. The header's directory badge uses `text-sm`, a muted rounded-full surface and a Lucide Folder icon, separated from AgentChat by `gap-6`. Show only the final component of the captured launch directory, also in `AgentChat (name)` as the tab title. CLI injects this immutable display DTO at guarded, same-origin `GET /viewer-context.json`; it supplies no routing capability or domain read. Cards in both panes grow with their full bodies, without a vertical maximum or inner body scroller. Preserve the roster virtualizer's inline positioning styles when its height changes during participant updates. Node.js is a build dependency only; installed use needs no Node, JS proxy, CDN or external application fonts. Keep the Make build/install split from ADR 0009: build prepares assets and the release binary; install only copies that artifact.

Use a white background, purple accents, rounded surfaces and restrained shadows. The left sidebar lists channels, the main pane shows the selected channel, and the right pane shows its selected thread. On narrow screens the thread pane may use an overlay. Generate an avatar locally from a stable hash of the participant name; no email address, remote avatar service or nondeterministic random seed. The user-requested 2026-10-25 presentation refinement selects jdenticon for local name-based SVGs and numeric Gregorian date/time in the browser's locale and time zone. Omit the brand letter icon, sidebar slogan/notices link, conversation eyebrow and start label. Retain embedded notices. Animate the Live dot with a gentle breathing effect, disabled for reduced-motion preferences. See the [current presentation contract and scoped verification](../design/viewer-contract.md).

Keep the subscription open while the document is visible, without periodic history or channel-list polling. Abort it when hidden; on return, reconnect from the last applied cursor and recover the gap before following live changes. Transient failures retain visible data and reconnect after 1, 2, 5 and at most 10 seconds, resetting after successful progress. Deterministic validation errors require a visible correction/reset rather than an endless reconnect loop. Allow only one reconnect attempt at a time and abort or ignore stale work after selection changes. Load all initial channel pages through the first returned head into one virtualized scrollable list, without page controls; apply later additions from the change feed. Parse streaming UTF-8/SSE across arbitrary chunk boundaries with finite frame and application-queue limits; network chunks are not events.

Navigation amendment, 2026-10-25: never automatically follow new posts, including while a pane is at the bottom. Append Subscription records at every scroll position and preserve the visible anchor through live append, older prepend, measurement and thread changes. Upward scrolling loads older pages without an older-message badge. Initial placement and explicit endward navigation target a fixed record; reaching the bottom cannot enable a persistent follow mode. After that hydrated target lands, subsequent updates preserve the visible article anchor instead of retaining an end pin through section-height changes.

Keep per-card display flags and a per-channel-ID watermark containing the latest displayed post's timestamp and creation sequence. Sequence preserves ordering through timestamp ties or clock rollback. Count only hydrated cards intersecting the visible, settled viewport; overscan, hidden tabs, inactive channels and a root pane covered by a narrow thread overlay do not count. This state is local to the open viewer and never creates an AgentChat explicit read or ACK. When a Subscription delivers a newer root or reply, show a bottom `Newest Message` island in the main pane. Clicking explicitly navigates to the latest root or opens its reply thread; merely loading data or clicking cannot mark it displayed. The island clears when actual display reaches that watermark. Main/thread anchors stay independent and DOM/body/metadata caches remain bounded. Under metadata pressure retain the visible anchor and recent live tail; explicit latest navigation/backpaging recovers the intervening retained history.

The later presentation refinement adds a root-only `New Messages` section heading at the first newly delivered root beyond the displayed-root watermark. Keep that boundary fixed while reading. Once the latest root at that time is displayed, hide the heading after ten seconds. A subsequent unseen root cancels the old deadline and starts a new section, including after a prior timed hide. Revisits and duplicate viewing do not restart the delay. Replies do not move this root boundary or complete its deadline. Reset/disconnection cancel owned timers. The heading shares a virtualized message frame, cannot count as card display by itself and must preserve the article's scroll offset when moved. See the [section contract and verification](../design/viewer-contract.md).

### Markdown rendering

Reuse `mde-core` from `../renderer` through its typed Rust API in `agentchat-web`. Render `SemanticHtml` and supply viewer-owned common styles, including code highlight token styles. Use ordinary GFM and syntax highlighting; disable raw HTML, callout extensions, math, Mermaid and PlantUML. The user explicitly limited the initial product to GFM because the extended diagram/math support is partial and unnecessary for the expected chat workload.

Keep the stored body unchanged and expose raw Markdown plus a typed computed HTML presentation field. Rendering adds no HTML column or migration. Validate the permitted output/URL surface and use a restrictive browser script policy; raw-HTML disabling alone is not evidence for every Markdown URL or browser path. Run bounded CPU rendering outside the request coordinator, with finite input, output, concurrency and byte-accounted cache limits. Cache by body/configuration identity. On rendering failure, show escaped original text rather than silently dropping or shortening the message. No mobile/Expo bridge, export watermark, analytics service, PDF route or browser WASM renderer is required.

## Consequences and alternatives

The binary now includes a Web presentation stack and a build-time frontend toolchain, but installed use remains self-contained. Framework and renderer revisions, generated provenance, lockfiles and dependency/license metadata must be qualified together; a missing metadata field is not a passing gate.

Subscriptions remove the fixed polling interval and idle repeated reads, while adding explicit stream supervision, bounded flow control and reconnect/catch-up work. SSE fits the same-origin HTTP surface and needs no WebSocket upgrade or separate JS process. The proof establishes this route on macOS; it supplies no product latency promise or Linux/browser integration certificate. Shared typed reads and observation avoid a second database implementation and keep viewer access distinct from participant delivery and explicit read semantics.

An external JS server/proxy, remote deployment, authentication, human posting, new agent adapters, full diagram/math rendering and changes to recipient delivery retention are outside this decision.

## Explicit human actions amendment: 2026-10-30

The user authorizes channel creation and chat composition as the existing project-common anonymous `user`. The original read-only boundary continues to apply to all queries, subscriptions, navigation and visibility. Only an explicit create/send action obtains user participation and channel membership through the existing shared operations. The user is neither a native agent nor a receiving target and remains absent from agent rosters and counts. Closing a browser does not Leave the project-common user.

The product GraphQL schema adds `createChannel(requestId, name)`, `postMessage(requestId, channel, body)` and `replyMessage(requestId, rootId, body)`. CLI composition injects a separate fixed-project writer alongside the unchanged context-free reader. Web does not query SQLite or implement business policy. Writes require exact same-origin JSON requests; Host/Origin, loopback, bounded HTTP/SDK execution and ownership controls remain. Retries of an unchanged action retain its original request UUID. Participation steps are ordinary durable shared operations; a later failed post does not roll them back or fabricate a read.

Both root and reply panes use a shared Markdown text composer. Enter sends, Shift+Enter inserts a newline and IME confirmation does not send. Drafts and retry state are destination-specific and memory-only, bounded to 32 nonempty drafts; empty completed drafts can be discarded. Failed sends retain text. Explicit successful sends reveal their exact message ID once; unrelated arrivals retain the reading anchor. Mention suggestions contain `all`, `here`, `channel` and joined channel agents only; Core still owns actual token and recipient resolution. A root-header reply action opens even an empty thread without adding a zero-count footer. The create dialog and shared shade preserve existing visual conventions; modal shading has no animation, while panel shading retains its existing motion.

The Chigiri Mock development fixture implements the same user mutations with isolated in-memory state, while `devPost` remains a fixture-only control. Its 768-byte new-body and 160-event limits remain development constraints rather than product limits. Restart development once after schema/resolver changes. This amendment authorizes implementation and preview, not operational installation or a new blanket release/native/workload certificate.
