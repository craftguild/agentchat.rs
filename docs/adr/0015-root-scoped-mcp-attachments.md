# ADR 0015: immutable root attachments behind a retained MCP transport

## Status

Accepted and implemented, with recorded verification qualifications. Later scope is amended or superseded by [ADR 0025](0025-agentchat-naming-and-explicit-launch-participation.md), [ADR 0028](0028-managed-auto-join-and-conversation-following.md).

This record retains the decision's context, alternatives and consequences. Read it with the [current contracts](../README.md) and [verification scope](../guides/verification.md). Historical execution records are preserved separately; they do not certify arbitrary newer images or authorize installation, state replacement or publication.

## Context

Actual Claude 2.1.301 retains its physical MCP child across clear while changing the native root. Fresh per-call IDs identify the caller, but the spawn environment is stale. On both OSes the tested own-manifest connect API fails after normal old-MCP EOF. Keeping the physical-connection binding contract therefore blocks that automatic root-switch path. See identity evidence and the bounded reconnection result. The user selects the proposal to retain the communication transport and use separate fixed attachments per conversation.

## Decision

A Claude physical stdio connection may be an identity-free transport gateway. Each native root lifecycle has a distinct immutable application attachment. Retire and release the preceding attachment before activating its replacement; never reset a retired Server or transfer its unresolved join intent. The generic Server remains immutable. A gateway has no participation or runtime attachment of its own, and a call cannot create or switch lifecycle registrations.

Before a project context exists, a verified native root may own an immutable bootstrap attachment. Its fresh opaque lifecycle nonce is not an application context or participant. Explicit-path diagnostics and explicit initialization use the same application operations; supplied context IDs are rejected and no join, restoration or heartbeat can occur. Each call still requires fresh native root/lifecycle proof. Missing context or proof never implies bootstrap authority. ADR 0019 supersedes immediate Busy for transient verifier mutex contention: wait within the existing bounded verification deadline before consuming proof, then validate the current owner/lifecycle. Genuine deadline/capacity exhaustion remains retryable Busy before operation dispatch. A retry uses a fresh host call and preserves the semantic request; it cannot reuse consumed proof, switch scope or restore retired authority. An authoritative later callback retires this attachment before registering a fresh project context at a strictly higher shared generation; ordinary calls cannot perform that promotion. Both stages share the one-current/one-pending bound, retirement fences and owner-loss cleanup.

Capture the verified initializer's host/root identity before project creation. Pass it to initialization as host-only metadata, unavailable to tool/CLI/wire arguments. The shared initializer retains that same conversation actor after descriptor creation, preserving semantic request-key replay without weakening different-actor conflicts. It validates any simultaneous descriptor against that identity. The actor is fixed for a bootstrap key, including across a cancelled transition. This grants neither a participant identity nor wake support.

Each tool call requires fresh native tool-use correlation with the exact current lifecycle. A host verifier rejects missing, ambiguous, stale and replayed proof. Arguments, cwd, display name, PID alone, copied history and spawn environment are not routing authority. Capture the selected attachment before dispatch and fence late results/callbacks against retirement. A mutation may already have committed; original semantic request UUIDs remain its recovery mechanism.

Use one current/retiring attachment and one pending lifecycle key per physical owner. The host assigns a positive monotonic lifecycle generation before async work. Same-key activation is idempotent; old/conflicting generations cannot revive a retired root. Cancellation retains the transition intent. A bounded cleanup task survives lifecycle-caller cancellation and owner loss; replacement waits for cleanup. Retained public handles contain no lifecycle owner.

Clear retires A without leaving its retained identity; C starts unjoined. Verified resume creates a fresh descriptor/incarnation and restores the same retained conversation through the shared lifecycle operation. Fork F remains unjoined. Independent same-directory native owners have separate gateways. Neither registration nor restoration substitutes for host admission/presence.

The native observation supervisor remains bounded and coalesced. Ordinary native activity for the exact current root may restart it after exhausted startup attempts. This retries transport I/O only: pause, lifecycle floors, per-call nonce proof, participation and profile admission are preserved. No periodic recovery scheduler or cached-presence fallback is introduced.

Preserve session-based MCP negotiation, all 24 typed tools, shared application operations, explicit invitation, host controls and bounded transport limits. Installed lifecycle hooks remain inert outside initialized projects. No launcher, manual per-clear reconnect, global message broker or extra model call is added. Codex's affirmative attached-frontend requirement is unchanged.
